# 04. Mobile app (Flutter)

One Flutter app for iOS 16+ and Android 9+ (API 28+) (NF-01). Customer mode and Business mode share the codebase; which one the app opens depends on the role of the logged-in user.

## 1. Packages

Use the latest stable versions at project start, and pin them in `pubspec.lock`.

| Purpose | Package |
|---|---|
| Backend | `supabase_flutter` |
| State | `flutter_riverpod`, `riverpod_annotation`, `riverpod_generator` |
| Routing | `go_router` |
| Models | `freezed`, `freezed_annotation`, `json_serializable` |
| Location | `geolocator` |
| Directions, links | `url_launcher` |
| Photos | `image_picker`, `flutter_image_compress` |
| Images | `cached_network_image` |
| QR | `qr_flutter` (show), `mobile_scanner` (scan) |
| Push | `firebase_core`, `firebase_messaging`, `flutter_local_notifications` (to show notifications while the app is open) |
| Crashes | `firebase_crashlytics` |
| Local storage | `shared_preferences` (basket, area, cached pickup passes) |
| Connectivity | `connectivity_plus` |
| Files | `path_provider`, `share_plus` (report download) |
| Formatting, l10n | `intl`, `flutter_localizations` (`gen-l10n`) |
| Lints and tests | `flutter_lints` (strict set in `analysis_options.yaml`), `mocktail` |

Do not add analytics, payment or maps SDKs (they are out of scope).

## 2. Folder structure (feature-first)

```
app/lib/
├── main.dart                   # reads FLAVOR from --dart-define-from-file, calls bootstrap()
├── bootstrap.dart              # Firebase, Supabase, Crashlytics, ProviderScope
├── core/
│   ├── config/                 # Env (from --dart-define-from-file), flavor
│   ├── router/                 # app_router.dart, route names, redirects
│   ├── theme/                  # tokens, ThemeData, text styles
│   ├── widgets/                # buttons, cards, badges, empty/error/loading, offline banner
│   ├── errors/                 # AppException, SIxxx → message map
│   ├── supabase/               # client provider, rpc helper
│   ├── push/                   # FCM init, token upsert, tap routing
│   └── utils/                  # money (AED), time (Asia/Dubai display), validators
├── l10n/app_en.arb
└── features/
    ├── onboarding/             # walkthrough (C-29)
    ├── auth/                   # email-first sign-in, code, complete profile, session, business login, terms
    ├── location/               # permission explainer, area picker, current origin
    ├── discovery/              # explore list, filters, search
    ├── restaurant/             # restaurant page, item sheet
    ├── basket/                 # basket state + screen, confirm reservation
    ├── orders/                 # orders list, details, pickup pass, offline cache
    ├── profile/                # profile, edit, delete account, legal
    └── business/
        ├── today/  window/  listings/  orders/  scan/  reports/  account/
```

Each feature folder contains:
- `data/`: repositories that call Supabase and return models
- `domain/`: freezed models
- `presentation/`: screens, widgets, and Riverpod controllers

Screens never call Supabase directly.

## 3. Flavors and config (no Mac)

- **Two flavors:** `dev` and `prod`.
  - **Android:** real `productFlavors` (`dev` and `prod`), each with its own application ID and `google-services.json` under `android/app/src/{flavor}/`.
  - **iOS:** a single Runner target with no extra schemes, because those need Xcode. Codemagic sets the bundle ID and display name before each build (see `13-ci-cd.md` §4). iOS builds never pass `--flavor`.
- **Env files:** `app/env/{dev,prod}.json` hold `FLAVOR`, `SUPABASE_URL` and `SUPABASE_ANON_KEY`, and are loaded with `--dart-define-from-file`.
  - The files are git-ignored; `env/example.json` is committed.
  - Pipelines write them from secrets.
- **App name:** "Save It" in the app, the stores, and emails (Q-04). Dev builds are "Save It Dev". Both platforms are built now. On-device acceptance waits until a test phone is available.
- **Firebase:** initialised in Dart with `lib/firebase_options_dev.dart` or `lib/firebase_options_prod.dart` (generated by `flutterfire configure`), picked by `FLAVOR`. Android also keeps `google-services.json` per flavor. The iOS `GoogleService-Info.plist` copies in `app/ios/config/{dev,prod}/` are used only to upload Crashlytics symbols. None of these files are secret.

**Redirect rules:**
- A restaurant user is always sent to `/business/*`.
- A customer is never sent there.
- A logged-in restaurant user who hasn't accepted the terms is sent to `/business/terms`.
- A signed-in customer with an incomplete profile is sent to `/auth/profile` before anything that needs an account.
- A guest who taps Reserve sees C-12, and returns to `/checkout` after signing in. The basket is kept. The same return-to-origin applies when sign-in starts from Orders or Profile.

## 5. Behaviour notes

- **Location (CA-02):**
  - Ask permission after the explainer screen.
  - If permission is denied, or no position arrives within 8 seconds, go to the area picker.
  - Store the chosen origin (GPS or area) and show it in the Explore header.
  - Refresh the GPS position on app resume if it is older than 10 minutes.
- **Explore (NF-03):** a single `nearby_restaurants` call, then pull-to-refresh. Show skeleton cards while loading and use cached logos. Target: list on screen within 3 seconds on 4G.
- **Basket (CA-10):**
  - Riverpod notifier, saved to `shared_preferences` so it survives restarts.
  - Holds `restaurant_id` and `{listing_id, qty, name, price}`.
  - When the restaurant page loads, the basket is checked again against current stock and limits.
- **Reserve (CA-11):** call `reserve_order`.
  - On SI005 or SI006, highlight the item named in `detail.listing_id`, update its available quantity, and show C-17.
  - On SI002, show C-26.
- **Pickup pass (CA-13):**
  - The QR payload is `saveit:v1:{code}`.
  - After a successful reservation and on every orders refresh, the pass is saved to `shared_preferences` under `pass_cache`: active orders only, with code, restaurant name, address, lat/lng, window, items and total.
  - When offline, `/orders/:id` shows the cached pass with the offline banner.
  - The countdown uses the stored `window_end`.
- **Session (CA-04):** Supabase refreshes tokens automatically. The 30-day inactivity timeout is configured in Supabase Auth (Pro). When the session expires, the app returns to the guest state and keeps the basket.
- **Push (CA-15, BM-07):**
  - Ask for permission after the first reservation (C-18). Restaurants are asked at first login.
  - Save the FCM token with `device_tokens`; delete it on logout.
  - While the app is open, show notifications with `flutter_local_notifications`.
  - Tapping a notification opens the screen named in its data payload: `{route: "/orders/<id>"}` or `{route: "/business/orders/<id>"}`.
- **Photos (BM-03):**
  - Take a photo or choose one from the gallery.
  - Compress to max 1200 px, JPEG quality 80, then upload to `listing-photos/{restaurant_id}/{uuid}.jpg`.
  - Listings without a photo show a default image by category.
- **Delete account (CA-05):** if `delete-account` returns SI060, show the active-order dialog with "View order".
- **Suspended restaurant (BM-12):** `today_summary` returns the restaurant status. When suspended, show the banner and disable Add listing, Repeat yesterday and Publish; scanning and orders still work.
- **Scan (BM-09):**
  - `mobile_scanner` with a torch toggle.
  - Accept only the `saveit:v1:` prefix, and stop scanning after the first match.
  - Manual entry is case-insensitive and ignores spaces.
- **Reports (BM-11):** call the `payout-report` Edge Function, save the file to temporary storage, and open the share sheet so staff can save or send it.
- **Accessibility (NF-09):**
  - Text follows the system text size, limited to 1.3× only where the layout would break.
  - All buttons have semantics labels.
  - Colour contrast meets AA (checked in T11.3).
- **Permissions strings:**
  - iOS needs `NSLocationWhenInUseUsageDescription`, `NSCameraUsageDescription` and `NSPhotoLibraryUsageDescription`.
  - Android 13+ needs `POST_NOTIFICATIONS` (requested at runtime).
- **Prices:** shown as `AED 15.00 incl. VAT`. Prices are VAT-inclusive (Q-02).
- **Supplied copy and art** live in `docs/businessrules-and-contents/`. Use these strings rather than placeholder copy:
  - Walkthrough (C-29), with the illustrations named beside them: "Save food, Save money!" and "Join many others in reducing food waste as food venues around Abu Dhabi share their surplus food every evening at a discounted rate! Why let good food go to waste?" (`Cycle.png`); "Make your reservation" and "Select what you want and get a unique pick up code, in just a few taps!"
